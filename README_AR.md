# apk-engine v0.2 — المشروع الكامل (محرك + موقع + حاوية)

الوظيفة الوحيدة: **ZIP لمشروع Android أصلي ← بناء Gradle ← تنزيل APK (أو سبب الفشل)**.

## المحتوى
| المسار | الوظيفة |
|---|---|
| `engine/apkengine.py` | المحرك: استخراج آمن، اكتشاف، بناء، جمع APK، تشخيص |
| `engine/test_apkengine.py` | 24 اختباراً للمحرك |
| `server/server.py` | الخدمة: رفع، طابور، تشغيل الحاوية، تنزيل، تنظيف |
| `server/web/` | صفحة الموقع العربية (`index.html` و`app.js` و`style.css`) |
| `server/test_server.py` | 13 اختباراً للخدمة |
| `docker/Dockerfile` | صورة البناء (حاوية لكل بناء) |
| `THIRD_PARTY_NOTICES.md` | إشعار MIT الخاص بـ AndroidForge (لا تحذفه) |

## ما اختُبر وما لم يُختبر
- **اختُبر محلياً:** كل اختبارات المحرك والخدمة (37 اختباراً)، وتجربة تكامل كاملة: رفع ← طابور ← محرك ← تنزيل APK ← حذف الملفات المؤقتة.
- **اختُبر بمحاكاة فقط:** Gradle (محاكى)، وأمر `docker run` (يُبنى ويُفحص نصّه فقط).
- **لم يُختبر أبداً:** بناء Gradle حقيقي، وبناء صورة Docker، وتشغيل الحاوية، وشكل الصفحة على شاشة حقيقية، وتحميلها على جوال.
- جدول AGP←Gradle/JDK (`AGP_RULES` في المحرك) يحتاج مطابقة مع الوثائق الرسمية.

## ما يفعله النظام للحماية
- معرّف الطلب عشوائي (128 بت على الأقل) ولا توجد قائمة طلبات؛ لا يصل مستخدم لملفات غيره.
- حد حجم الرفع، وفحص توقيع ZIP، وحد 5 رفعات/ساعة لكل IP، وطابور محدود.
- يُحذف الـ ZIP والمجلد المؤقت فور انتهاء البناء، ويُحذف الناتج بعد 60 دقيقة.
- كل بناء في حاوية: غير root، بلا صلاحيات (`--cap-drop ALL`)، حدود ذاكرة ومعالج وعمليات، ومهلة.
- لا مسارات خادم في الردود، وترويسات أمان على الصفحة والتنزيل.

## التشغيل على خادم Linux (لاحقاً، بعد نجاح التجربة وقرارك)
المتطلبات: Linux x86-64، Docker، Python 3.9+، ذاكرة 8 GB فأكثر، 40 GB قرص.
1. فكّ الحزمة، ثم من جذرها: `docker build -f docker/Dockerfile -t apkengine-builder:latest .`
2. شغّل الخدمة بمستخدم عادي ضمن مجموعة docker (وليس root):
   `DATA_DIR=/var/lib/apkengine TRUST_PROXY=1 python3 server/server.py`
3. ضع خلفها وكيلاً عكسياً بـ HTTPS (Caddy أو nginx) وارفع حد حجم الطلب فيه ليساوي `MAX_UPLOAD_MB`.
4. قيّد خروج الحاويات: أنشئ شبكة Docker خاصة (`DOCKER_NETWORK`) وامنع منها عناوين الشبكات الداخلية وعنوان بيانات السحابة `169.254.169.254` بجدار الحماية. **هذا غير منفَّذ تلقائياً** ويجب إعداده يدوياً.

للتطوير فقط (بلا عزل!): `RUNNER=local APKENGINE_ALLOW_LOCAL=1 python3 server/server.py`

## الإعدادات (متغيرات بيئة)
`PORT` (8080) · `HOST` (127.0.0.1) · `DATA_DIR` · `MAX_UPLOAD_MB` (100) · `MAX_CONCURRENT` (1) · `QUEUE_MAX` (10) · `RATE_PER_HOUR` (5) · `JOB_TTL_MIN` (60) · `BUILD_TIMEOUT` (1500 ثانية) · `DOCKER_IMAGE` · `DOCKER_MEMORY` (6g) · `DOCKER_CPUS` (2) · `DOCKER_NETWORK` (bridge) · `TRUST_PROXY` (1 خلف وكيل موثوق)

## القيود المعروفة
- كل بناء ينزّل Gradle والمكتبات من جديد (لا كاش مشترك، حفاظاً على العزل): البناء بطيء ويستهلك نطاقاً ترددياً. الكاش الآمن المشترك مرحلة لاحقة.
- الطابور في الذاكرة: يضيع عند إعادة تشغيل الخدمة.
- الخدمة تحتاج صلاحية Docker، فاختراقها يعني خطراً على الخادم؛ شغّلها على خادم مخصص لهذا الغرض فقط.
- منصات SDK غير المثبتة في الصورة (غير 34 و35) تُنزَّل أثناء البناء وقد تفشل.
- التوقيع debug فقط، وكل بناء بمفتاح جديد.
- التجربة الحالية على GitHub تبقى بحزمة v0.1 (المحرك نفسه، مع إضافتين صغيرتين هنا: مجلد `/opt/jdks` وملف تقدّم البناء).
